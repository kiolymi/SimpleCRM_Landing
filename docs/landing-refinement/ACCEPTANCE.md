# Проверяемые условия готовности

Эти критерии задают смысл «до идеала» для текущего объёма. Их нельзя ослабить ради завершения. Непроверенное не считается успешным. Публикация не требуется и не разрешена автоматически.

## Обязательные критерии

| ID | Условие | Доказательство |
|---|---|---|
| SAFE_GIT | Исходная история сохранена, изменения в новой ветке | baseline SHA, branch, diff, scoped commits |
| SAFE_FIGMA | Оригиналы и общие master-компоненты не изменены | manifest оригинальных/новых IDs, визуальное сравнение |
| HERO | Видео и фон не масштабируются/не удлиняются от hover телефона | измерения до/во время/после и видео/кадры |
| AUDIENCE | Нетехническому специалисту понятны назначение и ситуации | тексты, сценарный walkthrough; не имитация интервью |
| THREE_STORIES | Три основные ситуации видны без скрытых вкладок | desktop/mobile screenshots |
| TWO_ROLES | Различены действия специалиста, клиента и системы | flows, подписи, прототип |
| TRUTH | Публичные обещания соответствуют проверенному статусу | product-truth и сопоставление текстов |
| COMMERCIAL | Нет неподтверждённых цен, сроков и гарантий | источник решения или честное исключение утверждения |
| CTA_MEANING | Название основной кнопки соответствует следующему действию | walkthrough всей цепочки |
| CTA_DELIVERY | Есть реальный разрешённый путь установки/регистрации/обращения | проверенная действующая ссылка либо подтверждение разрешённого теста доставки; локальный toast недостаточен |
| FIGMA_READY | Нужные копии экранов созданы и визуально проверены | ссылки, экспорт, прототип и проверенные состояния |
| VISUALS | Визуалы осмысленны и согласованы, UI точный | assets-manifest и просмотр |
| COPY | Нет лишних дублей, жаргона, конфликтующих названий | редакционный аудит и итоговая страница |
| MOBILE | Нет обрезки/overflow, удобное управление на малом экране | проверки 360/390/768/1024/1440, отдельные ограничения среды |
| ACCESS | Клавиатура, focus, читаемость, масштабирование и reduced-motion | протокол фактических проверок |
| LINKS | Важные старые и новые маршруты открываются напрямую | журнал ссылок с base path |
| FORMS | Корректны обязательные поля, ошибки, повтор и результат | тесты; отправка только с разрешением |
| MEDIA | Нет неоправданной загрузки, визуальных скачков и ошибок медиа | размеры, сетевые ошибки, сравнение baseline |
| CONSISTENCY | Главная, FAQ, about, pricing, support и learn не противоречат | cross-page audit |
| DEMO_SAFETY | Интерактивные примеры не выполняют реальные платежи/отправки | проверка обработчиков и сценариев |
| QA_FINAL | Пройдены два разных полных аудита итоговой версии | audit A и B с одним SHA/tree fingerprint |
| HANDOFF | Результат можно открыть, проверить и продолжить | handoff, preview URL, branch/SHA, ограничения |

## Дефекты

- P0: потеря оригиналов, секреты/персональные данные, опасное или неразрешённое действие.
- P1: основной путь не работает, существенное ложное обещание, критическая мобильная/доступностная проблема, регрессия hero.
- P2: заметная ошибка текста/компоновки/поведения, ухудшающая понимание.
- P3: необязательная идея или предпочтение без доказанного нарушения требований.

Для завершения P0/P1 должны быть устранены. P2 — исправлены либо явно приняты пользователем с ID решения и причиной. P3 не продлевает задачу бесконечно.
Отсутствие реального канала CTA — внешний блокер, не основание объявить фальшивую отправку нормой.
Проверка с реальными пользователями желательна и планируется отдельно; без неё запрещено заявлять подтверждённую конверсию/понятность всей аудитории. Собственный аудит не заменяет исследование.

## Формат финальных доказательств

В outputs/14-refinement-loop.md перечислить каждый ID: PASS/FAIL/NOT_VERIFIED, evidence path, версия, дата, ограничения.
Два полных прохода: A — содержание и путь пользователя; B — визуальное/функциональное качество. После значимых исправлений повторить затронутые проверки и получить оба прохода на итоговом состоянии.
Оценки вроде 10/10 и идеально не являются доказательством.
