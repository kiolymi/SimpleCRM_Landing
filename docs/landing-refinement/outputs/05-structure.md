## Путь посетителя

«Это для моей практики» → «Да, такая ситуация бывает» → «Вот как это можно организовать» → «Что будет у меня и что увидит клиент» → «Как начать и что уже доступно».

Не нужны отдельные гигантские блоки для каждой мысли. Узнаваемые ситуации объединяются с тремя сценариями, а доверие, условия и короткий FAQ — в один спокойный завершающий раздел.

## Три истории и интерактив

Все три названия, проблема и результат присутствуют в DOM и доступны в обычном чтении. Не использовать общие tabs для выбора одной пользы. Desktop: чередование изображения и текста, как в исходной основе, но без длинных повторяющихся абзацев. В каждой истории свой прогресс 1/2/3; переключаются только детали этой истории.

1. #story-return: договорились вернуться → задача на выбранную дату → черновик сообщения с решением специалиста. Видно, кто пишет; ничего не уходит само.
2. #story-payment: счёт к встрече → клиент видит сумму/условия → отдельный статус получения денег. Кнопка «Я оплатил» не равна получению платежа.
3. #story-booking: специалист выбирает доступное время → клиент выбирает → подтверждение или конфликт. Это новый проектный сценарий, не существующая интеграция.

Не все состояния выводить одновременно. Ошибки/пустые состояния доступны через отдельное «Другой случай» в расширенном прототипе, не конкурируют с первым знакомством.

## Mobile и доступность

Порядок DOM одинаков на всех ширинах: заголовок/проблема → визуал → действия/подробности. Чередование колонок desktop — только CSS, не перестановка смыслового tab-порядка. Карточки профессий на mobile в один столбец с короткими текстами; не горизонтальная карусель с невидимыми вариантами. Сценарии вертикально, каждый с отдельным доступным заголовком.

На 360–390 px экран не должен требовать чтения мелкого текста внутри уменьшенного телефона: смысл и состояния дублируются обычным текстом рядом. У деталей раскрывающая кнопка с aria-expanded/controls; фокус видим. Hover — дополнительный блик, не способ получить нужную информацию. Крупные зоны нажатия; reduced-motion и сохранение высоты на смене шага. 200% zoom проверяется позже, не объявлен пройденным здесь.

## Навигация

Desktop: «Как помогает» → /#practice, «О продукте» → /about/, «Вопросы» → /faq/, «Поддержка» → /support/ + основной CTA. Бренд ведёт на /. Тарифы, материалы, версии и конфиденциальность — в футере; тарифная страница остаётся, но не рекламирует неутверждённую цену.

Mobile: та же верхняя группа, затем компактный дополнительный список в меню. Материалы доступны одним нажатием без вложенного меню. Сохранять поиск внутри каталога, не дублировать его первым большим полем в общем меню. Поддержка и политика доступны на каждой странице. На дочерних страницах якоря используют /#practice и /#start с учётом существующего base path GitHub Pages.

## Альтернативы и выбор

- Рекомендуемый A005 — сохранить профессиональные карточки и последовательные сцены; достоинство: узнаваемая основа, минимальная перестройка. Цена: страница длиннее, поэтому короткие тексты и один экран истории вместо трёх повторов обязательны.
- Альтернатива 1 — сразу после hero три компактные сценарные карточки, профессии ниже. Быстрее показывает пользу, но слабее отвечает «для меня ли это» и сильнее меняет уже выбранную композицию.
- Альтернатива 2 — один интерактивный симулятор рабочего дня. Даёт связность, но прячет две пользы, сложнее с клавиатуры/mobile и создаёт впечатление готового приложения. Для текущей цели отклонён.
