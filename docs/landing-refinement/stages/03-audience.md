# Этап 03 — Описать аудиторию и узнаваемые ситуации

## Режим запуска

Этот файл — инструкция только для одного этапа, не shell-скрипт.
Корень пакета: docs/landing-refinement/ в исходном репозитории SimpleCRM_Landing.
До действий прочитай README.md, COMMON.md, STATE.json, DECISIONS.md и ISSUES.md из корня пакета. Пути ниже относительны корню пакета.
При ручном запуске выполни только этот этап и остановись. При запуске через GOAL.md передай управление его последовательному циклу. Не запускай следующие этапы параллельно и не создавай другие задачи/агентов.
Этап 02 должен иметь статус passed. Если обязательный результат отсутствует, вернись к нему; не подменяй его предположением.

## Цель этапа

Сформулировать пользу для специалистов по записи простым человеческим языком.

## Входные материалы

- outputs/02-product-truth.md

## Что сделать

1. Опиши общий способ работы: индивидуальные записи, повторные обращения, переносы, оплаты, переписка, самостоятельная практика или небольшой помощник. Не ограничивай продукт психологами и тренерами.
2. Для психолога/коуча, тренера/инструктора, преподавателя/консультанта и мастера услуг составь короткие ситуации. Отдели подтверждённые наблюдения от предположений для проверки.
3. Для повторной записи, оплаты и выбора времени опиши: триггер, текущий обходной способ, затруднение, желаемый результат, возражение и подходящее доказательство в интерфейсе.
4. Определи нейтральную лексику и локальные варианты названий услуг. Не используй агрессивный дожим, чувство вины или обещание обязательного возврата клиентов. Интервал повторного контакта выбирает специалист.
5. Составь словарь замен технических выражений. Уточни, что слова CRM, контекст, реактивация и автоматизация не должны заменять объяснение конкретного действия.
6. Сформулируй вопросы для будущей проверки на людях. Не представляй собственную роль психолога/тренера или ответы вымышленных персон как настоящее пользовательское исследование.

## Что сохранить

- outputs/03-audience.md
- Доказательства в evidence/03/ с датой, URL/узлом, размером экрана и состоянием проверенной версии.
- Запись этапа в RUN_LOG.md, обновления ISSUES.md, DECISIONS.md и STATE.json.

## Условия перехода

- [ ] Общие сценарии понятны без технических терминов.
- [ ] Есть несколько групп специалистов и осмысленные различия между примерами.
- [ ] Нет вымышленных интервью, статистики и отзывов.
- [ ] Сформулированы возражения, которые должен снять лендинг.
- [ ] Пройден локальный аудит этапа по COMMON.md; обязательные результаты не заменены обещанием.
- [ ] Отчёт содержит реальные доказательства и следующие действия, состояние сохранено.

Если переход невозможен, оставь этап needs_input или failed с точной причиной. Выполняй только независимые безопасные части этого же этапа. Не помечай зависимые этапы passed и не ослабляй критерии самостоятельно.
