# Этап 05 — Собрать структуру главной и убрать повторы

## Режим запуска

Этот файл — инструкция только для одного этапа, не shell-скрипт.
Корень пакета: docs/landing-refinement/ в исходном репозитории SimpleCRM_Landing.
До действий прочитай README.md, COMMON.md, STATE.json, DECISIONS.md и ISSUES.md из корня пакета. Пути ниже относительны корню пакета.
При ручном запуске выполни только этот этап и остановись. При запуске через GOAL.md передай управление его последовательному циклу. Не запускай следующие этапы параллельно и не создавай другие задачи/агентов.
Этап 04 должен иметь статус passed. Если обязательный результат отсутствует, вернись к нему; не подменяй его предположением.

## Цель этапа

Выстроить понятное чтение страницы с сохранением узнаваемой визуальной основы.

## Входные материалы

- outputs/02-product-truth.md
- outputs/03-audience.md
- outputs/04-conversion.md

## Что сделать

1. Составь таблицу существующих блоков: сохранить, сократить, переделать, переместить. Обоснуй каждое изменение конкретной задачей посетителя.
2. Сохрани видео и композицию hero; допускается уточнение пояснения и CTA. Не переписывай удачный заголовок ради новизны. Сохрани независимое плавное движение телефона.
3. Предложи основной порядок: hero, узнаваемые ситуации, три сценария, связанная история клиента, начало работы, доверие/условия/FAQ, финальный CTA. Не превращай пункты плана автоматически в девять гигантских одинаковых секций.
4. Уменьши дублирующие объяснения всё в одном месте. Карточки профессий должны помогать узнавать себя, а не отправлять читать инструкцию до понимания продукта.
5. Сделай все три основные пользы видимыми без переключения вкладок; интерактив оставь для подробностей. Продумай мобильный порядок.
6. Упрости основную навигацию, сохрани доступность поддержки и конфиденциальности. Материалы и версии не должны конкурировать с главным действием.
7. Запиши 1 рекомендуемую структуру и не более 2 альтернатив с реальными trade-offs. Для автономного режима выбери наиболее консервативный подход и занеси обратимое решение в DECISIONS.md.

## Что сохранить

- outputs/05-structure.md
- Доказательства в evidence/05/ с датой, URL/узлом, размером экрана и состоянием проверенной версии.
- Запись этапа в RUN_LOG.md, обновления ISSUES.md, DECISIONS.md и STATE.json.

## Условия перехода

- [ ] Для каждого блока определены задача, содержание, визуал и действие.
- [ ] Основные преимущества доступны без скрытых вкладок.
- [ ] Сохранены ценные существующие элементы.
- [ ] Есть план desktop/mobile и согласованный основной маршрут.
- [ ] Пройден локальный аудит этапа по COMMON.md; обязательные результаты не заменены обещанием.
- [ ] Отчёт содержит реальные доказательства и следующие действия, состояние сохранено.

Если переход невозможен, оставь этап needs_input или failed с точной причиной. Выполняй только независимые безопасные части этого же этапа. Не помечай зависимые этапы passed и не ослабляй критерии самостоятельно.
