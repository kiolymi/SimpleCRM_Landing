# Этап 08 — Доработать Figma в отдельной рабочей области

## Режим запуска

Этот файл — инструкция только для одного этапа, не shell-скрипт.
Корень пакета: docs/landing-refinement/ в исходном репозитории SimpleCRM_Landing.
До действий прочитай README.md, COMMON.md, STATE.json, DECISIONS.md и ISSUES.md из корня пакета. Пути ниже относительны корню пакета.
При ручном запуске выполни только этот этап и остановись. При запуске через GOAL.md передай управление его последовательному циклу. Не запускай следующие этапы параллельно и не создавай другие задачи/агентов.
Этап 07 должен иметь статус passed. Если обязательный результат отсутствует, вернись к нему; не подменяй его предположением.

## Цель этапа

Получить проверенные экраны, сохранив оригинальные макеты нетронутыми.

## Входные материалы

- outputs/01-baseline.md
- outputs/02-product-truth.md
- outputs/06-copy.md
- outputs/07-flows.md
- CONTEXT.md

## Что сделать

1. Используй доступные Figma tools и обязательные skills для чтения/редактирования. Начни с проверки текущего содержимого; прежние node IDs — ориентиры, не разрешение менять узел без просмотра.
2. Создай отдельную страницу или секцию CRM Landing — Practice Refinement — 2026-09. Скопируй туда нужные экраны. Запиши новые IDs и границы разрешённых изменений в manifest.
3. Не редактируй оригинальные экраны, общие master-компоненты, переменные и стили так, чтобы менялись старые результаты. При необходимости изолируй только копируемую зависимость и документируй это. Не переименовывай и не удаляй исходные страницы.
4. Переиспользуй существующую систему. Доработай Сегодня, карточку клиента, встречу, счёт, напоминания и просмотр сообщения в копиях. Добавь минимальные отсутствующие клиентские экраны самозаписи и подтверждения.
5. Сделай связный прототип трёх сценариев. Подписи услуг должны соответствовать частной практике; суммы, даты, имена и состояния должны быть согласованы. Используй только вымышленные сведения.
6. Проверь каждый новый экран визуально, включая ошибки и длинный текст. Экспортируй пригодные для сайта изображения без обрезанных элементов и без изменения оригиналов.
7. Если Figma недоступна, подготовь спецификацию и зафиксируй блокер. Не объявляй создание макета выполненным и не подменяй его AI-картинкой интерфейса.

## Условия перехода

- [ ] Изменения ограничены новой страницей/секцией и записанными новыми узлами.
- [ ] Оригинальные экраны и общие зависимости сохранены.
- [ ] Экранные состояния соответствуют сценариям и текстам.
- [ ] Есть проверенные скриншоты, ссылки и экспорт для реализации.
- [ ] Пройден локальный аудит этапа по COMMON.md; обязательные результаты не заменены обещанием.
- [ ] Отчёт содержит реальные доказательства и следующие действия, состояние сохранено.

Если переход невозможен, оставь этап needs_input или failed с точной причиной. Выполняй только независимые безопасные части этого же этапа. Не помечай зависимые этапы passed и не ослабляй критерии самостоятельно.
