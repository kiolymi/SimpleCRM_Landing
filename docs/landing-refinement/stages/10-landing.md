# Этап 10 — Реализовать главную в новой ветке

## Режим запуска

Этот файл — инструкция только для одного этапа, не shell-скрипт.
Корень пакета: docs/landing-refinement/ в исходном репозитории SimpleCRM_Landing.
До действий прочитай README.md, COMMON.md, STATE.json, DECISIONS.md и ISSUES.md из корня пакета. Пути ниже относительны корню пакета.
При ручном запуске выполни только этот этап и остановись. При запуске через GOAL.md передай управление его последовательному циклу. Не запускай следующие этапы параллельно и не создавай другие задачи/агентов.
Этап 09 должен иметь статус passed. Если обязательный результат отсутствует, вернись к нему; не подменяй его предположением.

## Цель этапа

Собрать работающую локальную версию согласованной истории, сохраняя исходный стиль.

## Что сделать

1. Повторно проверь ветку и scope. Сначала прочитай действующие инструкции и подходящие skills. Не мигрируй стек и хостинг; при конфликте обязательных требований останови только конфликтующее действие и запроси решение.
2. Реализуй небольшими порциями: один блок, локальная проверка, исправление, затем следующий блок. Используй существующие токены и компоненты. Не меняй весь CSS глобальными переопределениями без анализа каскада.
3. Сохрани hero-видео и геометрию фона. Hover-трансформация только на переднем изображении; длительности входа/выхода согласованы. Проверь размеры фона и секции до, во время и после наведения.
4. Сделай три сценария понятными без взаимодействия. Добавь ограниченные демонстрационные шаги на вымышленных данных, без отправок и платежей. Проектные будущие функции нельзя выдавать за уже доступные.
5. Подключи реальный CTA только по подтверждённым условиям этапа 04. Если нет канала, оставь честный локальный тестовый вариант и открытый release-блокер, не показывай ложную успешную доставку.
6. Обеспечь клавиатуру, focus, мобильное управление, корректные ссылки, alt-тексты, состояния ошибок, загрузку изображений и fallback. Не ставь production-трекеры и не передавай данные третьим лицам без разрешения.
7. После каждой части запиши что изменено и чем проверено. Делай адресные локальные checkpoint-коммиты только своих файлов, если Git разрешён. Не пушь и не деплой.
