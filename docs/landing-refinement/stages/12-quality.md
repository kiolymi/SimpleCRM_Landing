# Этап 12 — Провести функциональную и визуальную проверку

## Режим запуска

Этот файл — инструкция только для одного этапа, не shell-скрипт.
Корень пакета: docs/landing-refinement/ в исходном репозитории SimpleCRM_Landing.
До действий прочитай README.md, COMMON.md, STATE.json, DECISIONS.md и ISSUES.md из корня пакета. Пути ниже относительны корню пакета.
При ручном запуске выполни только этот этап и остановись. При запуске через GOAL.md передай управление его последовательному циклу. Не запускай следующие этапы параллельно и не создавай другие задачи/агентов.
Этап 11 должен иметь статус passed. Если обязательный результат отсутствует, вернись к нему; не подменяй его предположением.

## Цель этапа

Подтвердить качество доказательствами, а не самооценкой агента.

## Входные материалы

- ACCEPTANCE.md
- outputs/10-landing.md
- outputs/11-secondary-pages.md

## Что сделать

1. Составь и выполни матрицу проверок по ACCEPTANCE.md. Проверяй текущую рабочую версию, записывай commit или tree fingerprint, URL, viewport, инструмент и результат.
2. Проверь ширины 360, 390, 768, 1024, 1440 CSS px и увеличение текста/масштаб 200%, где инструменты позволяют. Непроверенную среду отметь явно; не выдавай один Chromium за проверку всех браузеров.
3. Проверь ссылки, прямые URL с base path, формы, focus/tab, Escape где уместно, ошибки, повторные действия, touch и reduced-motion. Реальные внешние отправки только с нужным разрешением.
4. Сравни hero до/hover/после: меняется только телефон, фон и границы секции остаются в пределах субпиксельной погрешности измерений, не появляется вертикальное продолжение фона.
5. Проверь читаемость, контраст, отступы, переносы, обрезку, отсутствие лишних рамок и горизонтального overflow. Осмотри фактические скриншоты, не ограничивайся DOM или зелёным тестом.
6. Проверь размеры медиа и сетевые/console ошибки. Используй реальные доступные команды проекта; если измерение Lighthouse недоступно, не выдумывай оценки. Сравни с baseline на сопоставимых условиях.
7. Занеси каждую проблему в ISSUES.md с воспроизведением, серьёзностью и критерием закрытия. Исправь доступное в рамках этапа, затем повтори затронутые и соседние проверки. Настоящие интервью не симулируй.

## Что сохранить

- Запись этапа в RUN_LOG.md, обновления ISSUES.md, DECISIONS.md и STATE.json.
