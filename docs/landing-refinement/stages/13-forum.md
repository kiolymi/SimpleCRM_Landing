# Этап 13 — Подготовить локальную версию к показу на форуме

## Режим запуска

Этот файл — инструкция только для одного этапа, не shell-скрипт.
Корень пакета: docs/landing-refinement/ в исходном репозитории SimpleCRM_Landing.
До действий прочитай README.md, COMMON.md, STATE.json, DECISIONS.md и ISSUES.md из корня пакета. Пути ниже относительны корню пакета.
При ручном запуске выполни только этот этап и остановись. При запуске через GOAL.md передай управление его последовательному циклу. Не запускай следующие этапы параллельно и не создавай другие задачи/агентов.
Этап 12 должен иметь статус passed. Если обязательный результат отсутствует, вернись к нему; не подменяй его предположением.

## Цель этапа

Проверить короткое знакомство с продуктом и подготовить материалы показа без публикации.

## Входные материалы

- outputs/02-product-truth.md
- outputs/04-conversion.md
- outputs/12-quality.md

## Что сделать

1. Пройди короткий маршрут посетителя: открыть главную, узнать ситуацию, посмотреть пример, понять готовность продукта, выбрать следующий шаг. Не требуется читать все статьи.
2. Подготовь краткий текст устного объяснения без IT-терминов, недоказанных процентов и демонстрации будущего как настоящего.
3. Проверь локальный просмотр на узком экране. Различай localhost и ссылку, доступную команде. Не называй старый опубликованный main обновлённой версией новой ветки.
4. Подготовь план проверки на 5–7 представителях аудитории: задачи, вопросы, способ записи проблем. Если люди не участвовали, отчёт должен содержать исследование не проведено, а не ответы вымышленных персон.
5. Подготовь статичный storyboard и перечень кадров для возможной PDF-презентации. Сам PDF и QR-код на новый публичный адрес создавай только при соответствующем запросе и существующем проверенном адресе.
6. Отдельно перечисли release-блокеры: канал заявок, готовность продукта, условия, устройства, непроверенные интеграции. Подготовка к показу не даёт разрешения на публикацию.

## Что сохранить

- outputs/13-forum.md
- Доказательства в evidence/13/ с датой, URL/узлом, размером экрана и состоянием проверенной версии.
- Запись этапа в RUN_LOG.md, обновления ISSUES.md, DECISIONS.md и STATE.json.

## Условия перехода

- [ ] Путь показа понятен без инструктажа по интерфейсу.
- [ ] Есть честное разграничение прототипа и действующей функции.
- [ ] Локальная ссылка не выдана за публичную.
- [ ] Непроведённые исследования и внешние блокеры явно отмечены.
- [ ] Пройден локальный аудит этапа по COMMON.md; обязательные результаты не заменены обещанием.
- [ ] Отчёт содержит реальные доказательства и следующие действия, состояние сохранено.

Если переход невозможен, оставь этап needs_input или failed с точной причиной. Выполняй только независимые безопасные части этого же этапа. Не помечай зависимые этапы passed и не ослабляй критерии самостоятельно.
