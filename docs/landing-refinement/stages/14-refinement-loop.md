# Этап 14 — Выполнить цикл независимых по задаче аудитов и исправлений

## Режим запуска

Этот файл — инструкция только для одного этапа, не shell-скрипт.
Корень пакета: docs/landing-refinement/ в исходном репозитории SimpleCRM_Landing.
До действий прочитай README.md, COMMON.md, STATE.json, DECISIONS.md и ISSUES.md из корня пакета. Пути ниже относительны корню пакета.
При ручном запуске выполни только этот этап и остановись. При запуске через GOAL.md передай управление его последовательному циклу. Не запускай следующие этапы параллельно и не создавай другие задачи/агентов.
Этап 13 должен иметь статус passed. Если обязательный результат отсутствует, вернись к нему; не подменяй его предположением.

## Цель этапа

Довести результат до критериев качества и остановить необоснованные переделки.

## Входные материалы

- ACCEPTANCE.md
- ISSUES.md
- DECISIONS.md
- outputs/12-quality.md
- outputs/13-forum.md

## Что сделать

1. Проведи полный проход A по содержанию и пути пользователя: аудитория, язык, доказуемость обещаний, три сценария, роли сторон, условия и CTA. Это собственный аудит, не независимое внешнее исследование.
2. Проведи отдельный полный проход B по фактическому результату: responsive, visual QA, accessibility, motion, ссылки, формы, ошибки, загрузка медиа и регрессия hero.
3. Для каждой находки укажи проверяемую проблему и ожидаемое улучшение. Не менять цвет, шрифт, структуру и изображения только потому, что можно придумать другой вариант.
4. Исправляй по одному связанному набору дефектов. После исправления повторяй соответствующий тест и зависимые проверки. Не переписывай уже принятые разделы без нового доказательства дефекта.
5. Для завершения нужны оба полных прохода на одном итоговом состоянии кода и assets, без открытых P0/P1 и без незавершённых обязательных проверок. Любая последующая значимая правка аннулирует затронутое подтверждение.
6. После трёх безрезультатных попыток одной проблемы останови ту же стратегию, разберись в причине, выбери безопасную альтернативу либо вынеси точный вопрос. Не помечай ошибку выполненной и не запускай бесконечные генерации.
7. Новые идеи вне scope занеси в future-backlog, не добавляй их в условия завершения. Неполученный доступ/ответ — external blocker, не повод менять защищённые исходники.
8. Если все критерии выполнены, переходи к передаче результата. Если нужен внешний ввод, запиши точку возобновления, сообщи что требуется и соблюдай правила среды для статуса длительной цели.

## Что сохранить

- outputs/14-refinement-loop.md
- Доказательства в evidence/14/ с датой, URL/узлом, размером экрана и состоянием проверенной версии.
- Запись этапа в RUN_LOG.md, обновления ISSUES.md, DECISIONS.md и STATE.json.

## Условия перехода

- [ ] Оба полных прохода относятся к одному итоговому состоянию.
- [ ] Нет открытых P0/P1 и скрытых обязательных проверок.
- [ ] Оставшиеся P2 согласованы пользователем либо исправлены.
- [ ] Изменения основаны на конкретных дефектах; бесконечной косметической ротации нет.
- [ ] Пройден локальный аудит этапа по COMMON.md; обязательные результаты не заменены обещанием.
- [ ] Отчёт содержит реальные доказательства и следующие действия, состояние сохранено.

Если переход невозможен, оставь этап needs_input или failed с точной причиной. Выполняй только независимые безопасные части этого же этапа. Не помечай зависимые этапы passed и не ослабляй критерии самостоятельно.
