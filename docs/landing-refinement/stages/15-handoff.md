# Этап 15 — Передать проверенный результат и сохранить историю

## Режим запуска

Этот файл — инструкция только для одного этапа, не shell-скрипт.
Корень пакета: docs/landing-refinement/ в исходном репозитории SimpleCRM_Landing.
До действий прочитай README.md, COMMON.md, STATE.json, DECISIONS.md и ISSUES.md из корня пакета. Пути ниже относительны корню пакета.
При ручном запуске выполни только этот этап и остановись. При запуске через GOAL.md передай управление его последовательному циклу. Не запускай следующие этапы параллельно и не создавай другие задачи/агентов.
Этап 14 должен иметь статус passed. Если обязательный результат отсутствует, вернись к нему; не подменяй его предположением.

## Цель этапа

Зафиксировать готовую версию новой ветки и понятные дальнейшие действия без самовольного релиза.

## Входные материалы

- STATE.json
- ACCEPTANCE.md
- ISSUES.md
- DECISIONS.md
- outputs/14-refinement-loop.md

## Что сделать

1. Сверь исходный SHA main/gh-pages с baseline. Проверь, что код приложения и документы изменялись только в целевой ветке, а оригинальная Figma сохранена.
2. Проверь git diff, staging и секреты. Не включай чужие файлы, DOCX встречи, аудио, модели распознавания, временные экспорты и личные данные. Коммить только собственные явно выбранные файлы, если разрешено.
3. Подготовь итоговый отчёт: что изменено, что сохранено, какие сценарии реализованы, какие функции только концепт, какие проверки действительно выполнены, что требует отдельного согласования.
4. Дай проверенный локальный URL, ссылки на новые Figma-экраны, ветку и SHA. Укажи ограничения локального просмотра. Не создавай публичный туннель без запроса.
5. Составь инструкцию будущей публикации и возврата к main без удаления новой ветки. Не выполняй push, merge, deploy, изменение DNS или gh-pages.
6. Проверь критерии ACCEPTANCE.md. Если есть release-блокеры или непроверенные обязательные действия, не объявляй идеал/полную готовность: выдай конкретный статус и следующий необходимый ввод.
7. Только при фактическом выполнении цели запиши завершение в STATE.json и завершай длительную цель штатным механизмом. Сохрани RUN_LOG.md и точные доказательства.

## Что сохранить

- outputs/15-handoff.md
- Доказательства в evidence/15/ с датой, URL/узлом, размером экрана и состоянием проверенной версии.
- Запись этапа в RUN_LOG.md, обновления ISSUES.md, DECISIONS.md и STATE.json.

## Условия перехода

- [ ] Прежние результаты сохранены и их ссылки/ориентиры указаны.
- [ ] Готовность подтверждена, ограничения не скрыты.
- [ ] Есть ветка, SHA, локальная ссылка и перечень тестов.
- [ ] Нет неразрешённой публикации и внешних действий.
- [ ] Пройден локальный аудит этапа по COMMON.md; обязательные результаты не заменены обещанием.
- [ ] Отчёт содержит реальные доказательства и следующие действия, состояние сохранено.

Если переход невозможен, оставь этап needs_input или failed с точной причиной. Выполняй только независимые безопасные части этого же этапа. Не помечай зависимые этапы passed и не ослабляй критерии самостоятельно.
